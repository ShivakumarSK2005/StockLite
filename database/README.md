# StockLite MySQL database files

Target: MySQL 8.0.16+.

## Run order
1. `schema.sql`
2. `triggers.sql`
3. `procedures.sql`
4. `views.sql`
5. `seed.sql` (development only)
6. `indexes.sql` only if you choose the optional query-specific indexes

Example using MySQL CLI:
```bash
mysql -u root -p < schema.sql
mysql -u root -p < triggers.sql
mysql -u root -p < procedures.sql
mysql -u root -p < views.sql
mysql -u root -p < seed.sql
```

Run each command from the directory containing the files. The optional `indexes.sql`
must not be rerun after its indexes already exist.

## Important design notes
- Products start with quantity 0. Use the stock procedures for all stock changes.
- `sp_stock_in`, `sp_stock_out`, and `sp_adjust_stock` own their transactions.
  Call them on a single acquired MySQL connection, and do not wrap the call in a
  second transaction.
- The procedures lock the product row using `SELECT ... FOR UPDATE`, so concurrent
  stock operations on the same product serialize.
- Stock movement rows store before/after quantities and are protected against
  update/delete by triggers. Use an adjustment procedure to correct mistakes.
- Product and user deletion is restricted by foreign keys when movement history
  exists. Use `is_active = FALSE` to archive/deactivate instead.
- The initial admin's password hash is a placeholder. Replace it with a real bcrypt
  hash generated by your backend before using the seed.
- Database objects alone do not implement authorization. The Express backend must
  authenticate users and enforce admin/employee permissions before calling procedures.
- For production-grade privilege separation, use a dedicated application DB user
  granted only required table/view/procedure permissions, rather than using root.


// DB Design 

Database object                 	Purpose
users             ->     Store users, password hashes, roles and active status
categories	      ->     Organize products into categories
products	        ->     Store SKU, price, current quantity and reorder level
stock_movements	  ->     Maintain an audit history of inventory changes
sp_stock_in	      ->     Increase inventory and record the movement atomically
sp_stock_out	    ->     Decrease inventory only when sufficient stock exists
sp_adjust_stock	  ->     Correct inventory with a mandatory reason
trg_stock_movements_before_update	 ->   Prevent editing historical movement records
trg_stock_movements_before_delete	 ->  Prevent deleting historical movement records
vw_inventory  ->	Show product details and calculated inventory value
vw_low_stock_products	 ->  Retrieve products that need replenishment
vw_recent_stock_movements  ->	Combine movement history with product and user details
vw_dashboard_summary	  ->  Calculate dashboard totals
Indexes and constraints	 ->  Support query performance and data integrity
